# 用户管理 / 权限管理 UI 审计与改造方案

日期：2026-09-03
交接：Codex → Claude Code
性质：只读审计与实施方案；Codex 未修改 `src/`

## 1. 审计范围

- `src/views/adminViews/page-users.vue`
- `src/views/adminViews/page-permissions.vue`
- 两页内的新增/编辑用户、重置密码、分配角色、新增/编辑角色、绑定权限、编辑权限项弹窗
- `src/components/common/AppBottomBar.vue`
- `src/styles/themes.css`
- 对照页：`page-login-logs.vue`（其 flex 页面壳和颜色变量用法更一致）

本轮不改接口、权限逻辑、角色分组规则、拖拽排序语义，也不调整 `AppBottomBar` 在其他业务页面的行为。

## 2. 已确认的问题

### P0：两个管理页违反同一个底栏布局契约

`AppBottomBar.vue` 明确要求父页面是 `height: 100vh + display:flex + flex-direction:column + overflow:hidden`。

- 用户管理基本满足 flex 契约，但页面根有四周 padding，底栏被包在内容内侧，看起来像一张悬空内容条，而不是应用级底栏。
- 权限管理使用 `min-height:100vh`、普通文档流和 `overflow-y:auto`，没有 flex column；`content-grid` 还使用与底栏高度无关的 `max-height:calc(100vh - 120px)`。结果是底栏位置由卡片内容高度决定，短内容时悬在中部，长内容时被推到首屏之外。
- 两页同属管理域却有两套页面几何规则：users 为 24px/40px/24px，permissions 为 32px/40px/48px。

这就是“底部状态栏脱离底部”的结构性根因，不能用 `position:fixed` 临时盖住。

### P0：文字颜色没有语义层级，主题切换后可读性不稳定

两页大量使用 `color:#000` 配合 `opacity:0.45/0.5/0.55/0.6/0.65`，同时 Element Plus 自己使用 `--el-text-color-*` 和主题主色：

- 自定义正文在三个主题中始终纯黑，破坏主题 B/C 的墨绿/墨蓝文字体系；
- 描述、空状态、权限数量、拖拽柄依靠父元素 opacity 变浅，实际对比度由背景混色决定，难以审计，也会连带影响子元素；
- `--text-muted` 本身在默认主题是 `#b09070`，用在小字号文字、状态栏用户名、占位符时偏浅；
- `el-tag type="info"` 承载原始权限码，但标签数量多、字号小、底色浅，成为“能看到块、读不清字”的主要区域；
- 必填星号使用黑色，与普通标签无法区分；危险操作与主操作的视觉权重也不稳定。

### P1：权限管理双列结构在低分辨率/缩放下失效

- `.content-grid` 永远 `1fr 1fr`，没有任何 `@media` 或 container query；
- 两列各自包含搜索框、长权限码、描述和操作按钮，窗口变窄后文本与按钮互相挤压；
- `.role-actions` 竖排在每行右侧，占据固定视觉宽度，进一步压缩角色主体；
- 卡片体使用两个独立的 `calc(100vh - ...)`，没有由页面剩余空间统一分配高度。

在 125%/150% 系统缩放下，常见 1366×768 屏幕会落入相当于 compact 的 CSS 可用区域，这不是手机适配问题，而是桌面紧凑布局缺失。

### P1：“分配角色”弹窗信息架构过载

当前 720px 弹窗在一个连续滚动区内混合：搜索、分组标题、复选框、角色名、描述、权限数量开关、权限码标签。

- 用户看不到“当前用户是谁”和“最终选择了几个角色”的持续上下文；
- 展开权限后大量技术权限码淹没角色名称，难以比较角色；
- 权限码没有模块分组和中文说明，只显示 code；
- 弹窗 footer 虽由 Element Plus 提供，但 body 自己 `max-height:640px`，未按视口扣除 header/footer，矮屏下可能让整个 dialog 超出可视区域；
- 行内 checkbox 可点击区域与右侧“权限数量”按钮属于两个交互目标，但视觉上没有清晰分区；
- 搜索为空时角色分组可用，搜索后仍保留复杂折叠语义，扫描效率低。

### P1：“绑定权限”与权限管理主列表也偏技术清单化

- 权限项以权限码为最大、最粗的主标题，中文名称/描述反而弱，管理者需要先读代码再理解用途；
- `role.permissions` 在角色卡中全部平铺，角色稍多就形成标签墙；
- 编辑/绑定/删除竖排在卡片右侧，扫描路径呈锯齿状；
- 权限管理左、右卡片都是独立滚动，但没有各自数量、已筛选状态和空结果清除入口。

### P2：用户表格操作与状态表达不够清楚

- “编辑 / 重置密码 / 分配角色”都是同级文字按钮，破坏性与高频操作没有分组；
- 用户状态（启用/禁用）没有形成高辨识度的状态列，角色为空、资料未补充均依赖低对比度浅字；
- “新增用户”单独占一条表格底栏且靠左，既不像表格工具栏，也不像页面主操作；当表格较空时更显得悬浮。

### P2：缺少管理页响应式与可读性自动化门禁

现有两页没有视口断点，也未发现针对管理页面、角色弹窗、底栏位置和文字对比层级的 Playwright 覆盖。后续很容易再次出现源码看似合理、实际缩放后裁切或 footer 漂移的问题。

## 3. 建议的视觉方向

采用“克制的后台工作台”而不是重新发明整套视觉：保留现有奶油纸质/墨青/墨蓝主题和 Element Plus，重点强化信息密度、稳定网格和可读层级。

记忆点应是：**角色与权限关系一眼可扫描**，而不是更多装饰。避免渐变大卡片、玻璃拟态和额外动画。

### 3.1 新增语义文字令牌

不要继续使用 `#000 + opacity`。建议在 `themes.css` 为每个主题补齐并直接使用不透明颜色：

```css
--text-strong: var(--text-primary);       /* 标题、角色名、用户名 */
--text-body: var(--text-secondary);       /* 正文、权限中文名 */
--text-subtle: #766858;                   /* 描述、数量，需逐主题给值 */
--text-disabled: #9b9185;                 /* 仅禁用态 */
--text-danger: #b42318;
--surface-subtle: var(--bg-table-header);
```

要求：

- 普通文字与背景对比度至少 4.5:1；18px/700 以上大字至少 3:1；
- `opacity` 只用于纯装饰图形，不用于承载信息的文字；
- 主色只用于可点击、选中和重点状态，不用于普通说明文字；
- 权限 code 用 12px 等宽字体，中文权限名用 13–14px 正文字体且作为第一视觉层。

### 3.2 统一后台页面壳

两页都改成同一种三段式结构：

```text
admin-page (100dvh, flex column, overflow hidden)
├─ admin-header       固定，不滚动
├─ admin-content      flex:1; min-height:0; 内部决定滚动
└─ AppBottomBar       50px，固定占据正常文档流底部
```

建议：

- 根容器不要直接 padding 包住底栏；padding 放到 `admin-header/admin-content`；
- 使用 `height:100dvh`，保留 `100vh` fallback；
- `AppBottomBar` 不改 fixed，不遮挡内容；
- 用户表格和权限卡片只在自己的内容区滚动；
- 统一水平边距 `clamp(16px, 3vw, 40px)`、区块间距 16px；
- 页面主操作放页头右侧：用户页“新增用户”，权限页“新增角色”。删除用户页空占一行的 `.table-footer`。

### 3.3 断点策略

复用现有响应式基线，不再新增一套数字：

- `>=1200px`：权限管理双列，建议角色侧 `minmax(420px, .9fr)`，权限侧 `minmax(460px, 1.1fr)`；
- `900–1199px`：双列改为可切换的分段 Tab（角色 / 权限项），避免两个窄栏硬挤；
- `<900px`：单列；页头操作收紧，表格允许横向滚动但操作列保持可达；
- 弹窗宽度用 `min(720px, calc(100vw - 32px))`，高度用 `min(760px, calc(100dvh - 32px))`。

## 4. 页面改造方案

### 4.1 用户管理

页头：

- 左侧保留返回/主页、标题；标题下可放“管理账号资料、角色和登录状态”的 12px 正常对比度说明；
- 右侧放“新增用户”主按钮；搜索和“共 N 位用户”放在表格卡片工具栏。

表格：

- 增加明确状态徽章（启用为中性绿，禁用为灰/红边），不要只靠浅色文字；
- 用户名单元格以显示名称为主、用户名为副；若业务更重视用户名则反过来，但两者必须形成主副层级；
- 部门与工号不要拼成 `— / —`，拆成主行与次行；缺失统一显示“未填写”；
- 操作列保留一个高频“编辑”，其余放入“更多”菜单：重置密码、分配角色、启用/禁用。危险项放菜单末尾并分隔；
- 只读用户不渲染空操作列。

### 4.2 分配角色弹窗

建议从“长列表弹窗”改为“选择工作台”：

```text
标题：为「显示名称 / username」分配角色
说明：角色决定该用户可访问的功能；管理员角色不可分配
搜索框                                      已选 3 个
┌ 角色分组与角色列表 ─────────────────────────────┐
│ [checkbox] 角色中文名/名称        6 项权限       │
│            一行描述                              │
│            [展开权限详情]                        │
└─────────────────────────────────────────────────┘
footer：恢复原选择（可选）             取消  保存角色
```

- Header 和 footer 固定，仅列表滚动；
- 角色行整行可点击，checkbox 不再是唯一命中区域；
- 选中行使用浅背景 + 左侧 3px 主色标识，不只改变 checkbox；
- 权限详情用次级区域，按权限码冒号前的域分组（account/product/shipping/...），中文描述优先，code 次级；
- 搜索结果直接展开匹配角色，不要求用户再展开分组；清空搜索恢复原折叠状态；
- footer 显示“已选 N 个角色”，保存按钮文案用“保存角色”，不要只写“确认”；
- 保持现有安全规则：admin 不出现在可分配列表，后端防线不变。

### 4.3 权限管理

- 角色侧每项只预览最多 3 个权限摘要，再显示“另 N 项”；完整权限放绑定面板，不在主列表制造标签墙；
- 操作改为行尾水平 `···` 菜单，或“绑定权限”作为唯一明显动作，编辑/删除进入次级菜单；
- 拖拽柄只在可拖动时显示，搜索状态下隐藏并提示“清除搜索后可排序”；
- 权限项侧以中文名称/描述为主，code 作为次行的等宽胶囊；
- 两张卡片 header 显示总数与筛选后数量，例如“角色 12 · 当前 4”；
- 分组标题使用粘性定位 `position:sticky; top:0`，长列表滚动时保留上下文；
- “重命名分组”改为小图标按钮或分组菜单，避免每个分组标题出现长文字动作。

### 4.4 绑定权限弹窗

- 标题带角色名：“为「售后编辑」绑定权限”；
- 顶部增加搜索、已选数量和“仅看已选”开关；
- 按权限域分组，每组支持全选/清空，但不要提供跨全部域的一键全选；
- 权限中文描述作为主文案，code 为副文案；
- footer 固定，并明确展示变更摘要：“新增 2，移除 1”；
- admin 若仍是全部权限的特殊语义，应展示只读说明，不打开一个看似可编辑的列表。

### 4.5 其他弹窗

- 新增/编辑用户、重置密码、新增/编辑角色统一 label 字号、间距、必填星号颜色；
- 表单错误紧邻字段，不只用全局 toast；
- 弹窗关闭前若有未保存修改，提示确认；
- 禁用输入框仍需保持文字可读，不能使用接近背景色的默认 disabled 色。

## 5. 建议实施顺序

### 第 0 批：视觉与布局基线

1. 增加管理页语义文字 token；
2. 抽取或至少统一 `admin-page/admin-header/admin-content` 页面壳；
3. 修复两页 AppBottomBar 正常流贴底；
4. 建立 8 档视口的管理页 Playwright fixture/API mock。

这一批不改交互结构，便于先验证底栏和可读性。

### 第 1 批：用户管理 + 分配角色

优先处理用户直接反馈最强的区域：表格层级、操作菜单、分配角色选择工作台。

### 第 2 批：权限管理 + 绑定权限

调整角色/权限主副层级、权限摘要、紧凑布局 Tab 和绑定权限工作台。

### 第 3 批：全主题、缩放与无障碍收口

对主题 A/B/C、键盘操作、焦点环、对比度、空状态和超长文本做统一验收。

## 6. 自动化验收要求

至少新增以下 Playwright 场景，API 全部打桩，不依赖生产账号：

1. 用户管理和权限管理各覆盖 1920×1080、1366×768、1093×614、911×512、844×390；
2. 每档断言无页面级横向溢出，主内容可滚动到达；
3. 底栏的下边缘与 viewport 下边缘重合（允许 1px 误差），且不遮挡最后一行内容；
4. 打开分配角色/绑定权限后，header 与 footer 可见，列表内部可滚动，保存按钮始终可达；
5. 长角色名、长中文描述、长权限码不覆盖 checkbox、数量和操作按钮；
6. 搜索、展开权限、选择角色、取消、保存完整交互；
7. account 只读权限下不出现写操作；
8. admin 不出现在可分配角色列表；
9. 主题 A/B/C 各跑一次关键文本的计算颜色检查，禁止信息文字使用 `opacity < 1`；
10. 收集 console error；复用现有可见性断言，补祖先裁切/遮挡检查。

人工验收补充：Windows 1366×768 下分别使用 100%、125%、150% 缩放，重点看分配角色、绑定权限和底栏。

## 7. 不建议的修法

- 不要全局把 `--text-muted` 改深来“一把梭”，会波及所有模块；先新增明确语义 token，再逐域迁移。
- 不要把 AppBottomBar 改成全局 fixed；它会遮挡其他页面，并掩盖父布局错误。
- 不要继续用 `#000 + opacity` 模拟层级。
- 不要只给权限标签换深色；当前问题同时包含信息架构、密度和滚动边界。
- 不要在本批顺带改后端权限语义或角色分组数据。
