## 阻塞问题：紧凑布局兜底被后续声明覆盖

在同一个 `@media (max-width: 1199px)` 中：

前面声明：

```css
.content-panel { overflow-y: auto; overflow-x: hidden; }
.chart-wrap { min-height: 220px; }
```

后面再次声明：

```css
.content-panel {
  display: grid;
  grid-template-rows: auto 1fr;
  overflow: hidden;
  min-height: 0;
}
.chart-wrap { min-height: 0; }
```

CSS 后声明优先，所以最终计算结果是：

- `.content-panel` 仍为 `overflow:hidden`；
- `.chart-wrap` 仍为 `min-height:0`。

这与代码注释、提交说明及本轮要解决的“宁可滚动，不要裁切”目标不一致。

## 建议返工方式

不要继续叠加第三组覆盖规则。把紧凑布局的 `.content-panel` 和 `.chart-wrap` 声明合并成唯一一处，明确最终契约。

建议目标：

- `.content-panel` 在内容超高时可纵向滚动；
- grid 第二行使用能表达最小图表高度的规则，例如 `minmax(220px, 1fr)`；
- 普通图表和地图 + Top10 都不依赖祖先 `overflow:hidden` 才能成立；
- 避免同时出现内容面板、图表容器、榜单列表三个相邻的纵向滚动条。保留哪个滚动层应由实际截图决定，但要有唯一主滚动责任。

具体 CSS 写法可由 Claude 根据实际页面高度调整，重点是最终计算样式不能再互相抵消。

## 必须补充的测试

### 1. 验证最终计算样式

在一个紧凑低高度视口下，直接断言：

- `.content-panel` 的最终 `overflow-y` 是预期值；
- 图表区域拥有约定的最小可用高度；
- 当人为制造内容超高时，主滚动容器满足 `scrollHeight > clientHeight` 且可以滚动到底部。

这能直接拦住本次“源代码看起来加了兜底，浏览器最终样式却被覆盖”的问题。

### 2. 覆盖筛选抽屉真实交互

当前用例只验证筛选按钮存在，没有点击抽屉。至少在一个 compact 档和一个手机档验证：

1. 点击筛选按钮；
2. 抽屉实际可见且中心点可命中；
3. 关键筛选控件可到达；
4. 点击关闭按钮或遮罩后抽屉关闭。

这才能证明“复用既有抽屉机制”在扩大到 `<1200px` 后没有交互回归。

### 3. 保留截图交叉验证

`elementFromPoint` 只验证中心点，不代表整个元素均未被部分裁切。试点阶段继续保留 1093×614、911×512、844×390 三档截图人工检查，等布局稳定后再决定是否增加截图基线。

## 非阻塞建议

- `elementFromPoint` 对固定悬浮层、加载遮罩和弹窗可能较敏感。后续公共使用时，应允许显式配置可接受的覆盖层，避免为了让测试通过而削弱断言。
- `<1200px` 的桌面用户也会进入抽屉模式，后续可以补键盘 Escape 关闭和焦点返回触发按钮；这不阻塞本次返工。
