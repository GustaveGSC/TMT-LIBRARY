# 物料停用改为只读（来源仅导入数据），交接 Codex

日期：2026-08-07
状态：**前端已改完并部署**；后端有一处死代码需要清理，不紧急但属隐患

## 用户决定（原文）

> 关于停用，我有个疑问，我是否需要去管这个物料是不是停用，因为我这个系统
> 并不和财务、采购有关系，只是用于售后、研发BOM的价格有关，那这个物料
> 停不停用其实无所谓。

> 取消「不显示停用状态数据」开关，保留停用状态列，取消三态，
> 并且取消卡片内可以人工设置停用（物料是否停用只来源于导入的数据）。

## 背景：查证结果

物料停用原先只影响一处，**研发 BOM 完全不看它**：

| 消费方 | 是否受影响 |
|---|---|
| BOM 成本（`rd/cost.py`） | ❌ 不看。那里唯一的 `is_disabled` 是 `erp_code_rules` 的规则禁用，与物料停用无关 |
| 物料清单 | 停用列 + 底部「不显示停用」开关（默认开） |
| 物料卡片 | 三态人工覆盖 |
| 组合物料选择器 | 曾传 `is_disabled: '0'`，停用物料**选不到** |

即真正起作用的只有「售后选件时会不会把停用物料挑出来」。而 2,919 条停用里
**2,897 条来自名称含「停用」关键词**、仅 265 条来自 ERP 状态——信号可靠性未知。

结论：**停用降级为提示，不参与任何过滤，也不可人工设置。**

## 前端已完成（`b6e...` 见提交）

1. 物料清单：**删除**「不显示停用状态数据」开关；停用状态列**保留**（含列筛选，可主动按停用筛）；删除「人工」角标；
2. 物料卡片：**删除三态选择**、**不再提交 `is_disabled`**；改为在 ERP 信息区只读展示「已停用 / 启用」角标，并显示 ERP `status`；
3. 组合选择器：**去掉 `is_disabged: '0'` 过滤**，停用物料可搜到、可加入组合，行内与明细里都标「已停用」角标。

## 需要 Codex 清理的：`product_material.is_disabled` 成了死列

生产实测该表当前 **0 行**，不存在任何已产生的人工覆盖，所以**无需数据清理**。

但代码路径还留着，是隐患：

1. **`save_item` 的 `allowed` 白名单里仍含 `is_disabled`**
   （`services/product/material.py:241` 附近）。前端现在不传了，
   但只要任何调用方传一次，就会重新产生人工覆盖、让该物料**永久脱离导入数据的判定**。
   → **从 `allowed` 里移除**，或显式忽略并在日志里告警。

2. **`effective_disabled_expression`** 里的 `case(ProductMaterial.is_disabled.is_not(None), ...)`
   分支永远走不到（override 恒为 NULL）。可简化为纯 ERP 判定：
   `status == '失效' OR coalesce(raw_name, name) LIKE 任一关键词`。
   简化后 `list_items` 的 `LEFT JOIN product_material` 是否还必需，请一并评估
   —— 它还要取 `short_name`，大概仍需保留。

3. **`is_disabled_override` 字段**可从 `_serialize` 的响应里去掉（前端已不读）。

4. **列本身删不删由你判断**：删列要一个迁移；不删则永远是 NULL 的死列。
   我倾向**保留列但移除代码路径**——万一将来又要人工覆盖，加回代码比加回列容易，
   且当前 0 行、留着零成本。你若认为该删，迁移由我部署。

## 不要动的部分

- **停用判定本身不变**：`status='失效'` 或 名称含配置关键词。
  `material_disable_keyword` 表与 `/disable-preview` 接口**继续保留**——
  关键词决定了列表里哪些显示为「停用」，仍然有用。
- `list_items` 的 `is_disabled` **请求参数保留**：停用状态列的列筛选在用它，
  用户仍可主动筛「只看停用」。只是不再有任何默认过滤。

## 我的验收方式

1. 卡片保存后 `product_material.is_disabled` 仍为 NULL（不产生覆盖）；
2. 即使请求体里恶意带上 `is_disabled: true`，该列仍为 NULL；
3. 停用状态列筛选「停用/启用」结果与关键词+ERP 状态的判定一致；
4. 组合选择器能搜到停用物料；
5. 回归：物料清单、组合、编码规则三个 tab 功能不受影响。

## 收口结论

物料停用现在是**纯只读的导入衍生值**：

```
停用 = (ERP status == '失效')  OR  (raw_name/name 含任一启用的停用关键词)
```

- 无人工覆盖入口，也无代码路径可写入；
- 不参与任何默认过滤，仅作展示 + 可主动筛选；
- 关键词表与 `/disable-preview` 保留，仍决定哪些显示为停用；
- `product_material.is_disabled` 列保留但恒为 NULL（0 行，留着零成本）。
