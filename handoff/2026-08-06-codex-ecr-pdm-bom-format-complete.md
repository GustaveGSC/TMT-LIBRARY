# ECR 支持 PDM 导出 BOM 格式完成，交接 Claude

日期：2026-08-06  
状态：代码完成、本地验证通过、**未部署**

## 实现范围

- 保留旧 ERP BOM 解析与 compare/output 契约。
- 新增 PDM BOM 自动识别：`物料编码 + 一级分类`。
- 校验与解析共用 `_bom_columns()`，避免两套表头规则分叉。

## 输入护栏

- 必需表头重复直接报错，消息包含名称、次数和列号；非必需重复取第一列。
- 无 ERP/PDM 特征列返回“无法识别的 BOM 文件格式”。
- 四个状态集中为模块常量；未知状态返回明确错误。
- 数字编码按整数文本读取；纯 0 的 Excel number format 用于恢复前导零；
  非整数 float 编码拒绝，避免 `.0`/科学计数静默污染。

## PDM 字段处理

- 图号：`物料编码-版本`；审核中新物料版本为空时解析阶段保留该行。
- 品名：一级/二级/三级分类去代码前缀后与描述用 `_` 连接，不使用四级分类。
- 产成品规格：系列版本、备注、类别、尺寸、材料、颜色及版本字母。
- 其他规格：适配产品、规格、表面处理/备注/颜色首个非空值、完整版本。
- PDM 新物料的规格版本槽使用 `A01`。

## 状态行为

- 已发布：保持原版本。
- 审核中：新物料，固定 `{code}-A01`，不调用 `_next_version`，不做空版本 replace。
- 通用变更审核中：原数字版本 +1。
- 非通用变更审核中：字母 +1、数字重置 01。

## 路由错误

`POST /api/rd/ecr/compare-bom` 现在会将解析阶段的 `UploadValidationError` 返回 HTTP 400，
不会落入统一 500。

## 验证

- 旧 ERP 版本变更快照测试保持原样通过。
- PDM 新物料解析、A01 图号、规格和 compare 新增行通过。
- PDM 产成品品名/规格通过。
- A01→A02、A01→B01 与新建 A01 三种状态互不干扰。
- 重复版本表头、未知状态、数字编码前导零均有回归测试。
- 全量 pytest、compileall、diff check 通过。

## 部署验收建议

本批无数据库迁移。部署后分别用一份旧 ERP 文件和用户的 PDM 文件走真实 HTTP：

1. 旧文件结果与历史快照一致。
2. 用户改名为“系列版本”后的 PDM 文件能识别并处理 122 行。
3. 保留两个“版本”的旧 PDM 文件明确 400，而不是静默覆盖。
4. 审核中新物料输出 `{code}-A01`，且规格未被空版本替换破坏。
5. journalctl 无 traceback，health/ready 正常。
