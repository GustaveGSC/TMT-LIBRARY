# “分配角色”面板专项返工方案

日期：2026-09-03
交接：Codex → Claude Code
依据：用户提供的生产实际截图
性质：UI 专项设计交接，不修改接口与权限业务规则

## 1. 结论

当前面板虽然已经加入搜索、分组、整行选择和固定 footer，但实际效果仍然不合格。根因不是局部颜色，而是把“角色选择”做成了“权限明细长表”：内容几乎占满整个窗口，用户仍然很难快速判断该选哪个角色。

本方案替代 `2026-09-03-codex-admin-ui-audit.md` 中对“分配角色”面板的概括建议；其他管理页建议仍然有效。

建议改成一个明确的**角色选择器**：

- 顶部只保留用户身份、搜索与已选角色摘要；
- 左侧是角色分类导航；
- 右侧用两列角色卡片展示可选角色；
- 权限明细通过右侧详情抽屉/Popover 按需查看，不在列表中原地展开；
- footer 只显示变更摘要和操作按钮。

## 2. 截图中确认的问题

### P0：说明与实际内容矛盾

标题下写着“管理员角色不可分配”，列表第一项却显示“管理员”及 checkbox。无论截图来自旧部署、缓存或当前分支，这都必须成为自动化断言：

```text
分配角色弹窗中永远不存在 name === 'admin' 的可见选项。
```

不要仅把 checkbox disabled 后继续展示。用户不需要在分配任务中看到一个永远不能选择的角色。

### P0：面板占用接近全屏，却没有形成有效的信息布局

- 截图约 1023×1040，dialog 几乎占满宽高；
- 角色仍然单列，每行只利用左侧约一半宽度，右侧大面积留白；
- 17 个左右的角色需要长距离滚动；
- footer 与滚动区贴得很近，最后一行呈现被截断的感觉；
- scrollbar 紧贴内容和 dialog 右边缘，缺少结束边界。

### P0：视觉层级粗糙

- 分组标题使用 2px 纯黑横线，视觉权重甚至高于角色名称；
- 展开箭头、分组数、权限数都像原始文本符号，没有组件化层级；
- 行分隔线过密，整体像 spreadsheet；
- 角色名、英文名称、中文说明在同一基线连续排布，文本之间没有稳定列宽或层级；
- “developer / manager / ops”等内部角色名比实际用途更醒目，管理人员首先看到的是技术命名。

### P1：选中反馈弱，摘要无信息

- 已选行仅靠很淡的绿底和左侧细线；在浅色显示器或高亮环境下不明显；
- 顶部“已选 4 个”和 footer“已选 4 个角色”重复，却都不显示具体角色；
- 用户无法快速确认新增了什么、取消了什么；
- 保存前没有“新增 N / 移除 N”的差异提示。

### P1：权限详情入口太弱且破坏列表稳定性

- “2 项权限 ▸”只有约 11px，命中区和可发现性都不足；
- 原地展开权限会改变下面所有行的位置，比较多个角色时频繁跳动；
- 技术权限码不是选择角色时的首要信息，不应占据主列表纵向空间。

### P1：命名没有面向使用者

系统角色同时显示 `developer / manager / ops` 和中文描述，但英文内部名称更粗、更靠前。部门角色又只有中文名称，两类角色视觉规则不一致。

角色主标题应优先显示业务名称：

- developer → 开发者
- manager → 管理者
- ops → 运维

内部 name 放在次级 code 胶囊中，例如 `developer`，用于识别而不是作为标题。部门角色没有单独显示名时可继续以 role.name 为标题。

如果后端没有 display_name 字段，本批可以在前端仅对三个内置角色维护一个明确映射；不要根据字符串自动猜。

## 3. 新布局

### 3.1 桌面布局（≥900px）

建议 dialog：

```css
width: min(920px, calc(100vw - 48px));
height: min(720px, calc(100dvh - 48px));
margin: 0;
display: grid;
grid-template-rows: auto minmax(0, 1fr) auto;
```

不要继续使用宽度 720 + 列表单列，也不要让 dialog 根据内容无限长高。

线框：

```text
┌──────────────────────────────────────────────────────────────┐
│ 分配角色                                      ×              │
│ 顾世昌 · gsc        角色决定用户可访问的功能                  │
│                                                              │
│ [ 搜索角色或权限                                      ]       │
│ 已选：[研发部 ×] [发货数据查看 ×] [售后数据查看 ×] [+1]      │
├───────────────┬──────────────────────────────────────────────┤
│ 全部角色   16 │  研发部                                      │
│ 已选择      4 │  ┌──────────────┐ ┌──────────────┐           │
│               │  │ ✓ 研发部      │ │  研发部管理员│           │
│ 系统角色    3 │  │ 研发工具基础… │ │ 管理研发配置…│           │
│ 部门角色    4 │  │ 5 项权限  查看│ │ 5 项权限  查看│           │
│ 功能角色    9 │  └──────────────┘ └──────────────┘           │
│               │                                              │
│               │  功能角色                                    │
│               │  ┌──────────────┐ ┌──────────────┐           │
│               │  │ ✓ 发货数据查看│ │ 发货数据管理  │           │
│               │  └──────────────┘ └──────────────┘           │
├───────────────┴──────────────────────────────────────────────┤
│ 新增 1 · 移除 0                         取消    保存角色      │
└──────────────────────────────────────────────────────────────┘
```

结构要求：

- header、搜索/摘要区、footer 均不滚动；
- 中间区域 `min-height:0`；只有右侧角色卡片区滚动；
- 左侧分类导航宽 176–196px，不和右侧一起滚动；
- 右侧使用两列 `repeat(2, minmax(0, 1fr))`；
- 分类标题可以出现在卡片流内，但使用小号文字和浅底分隔，不使用纯黑横线；
- 滚动区四周保留 16px 内边距，scrollbar 不贴卡片文字。

### 3.2 紧凑布局（<900px）

- 左侧分类导航改为顶部横向 filter chips：全部 / 已选择 / 系统角色 / 部门角色 / 功能角色；
- 角色卡片变为单列；
- dialog 宽 `calc(100vw - 24px)`、高 `calc(100dvh - 24px)`；
- 已选角色摘要只展示前 2 个，剩余显示“另 N 个”；
- footer 保持可见，不允许按钮随列表滚走。

## 4. 角色卡片规格

每张卡片只放选择所需的信息：

```text
[checkbox]  发货数据查看                         [已选择]
            可查看发货分析、明细和图表
            2 项权限                         查看权限 ›
```

建议规格：

- 最小高度 92px，padding 14px 16px，圆角 10px；
- 默认边框 `var(--border)`，背景 `var(--bg-card)`；
- hover 只增强边框和轻微底色，不移动卡片；
- selected 使用 `border-color:var(--accent)` + 明确的浅色背景 + 右上“已选择”徽章；
- checkbox 与整张卡片同步，整卡可点击；
- 中文业务名 14px/700，内部 code 11px 等宽次级色；
- 描述最多两行，超出省略；禁止与标题挤在同一行；
- 权限数量使用正常 12px 对比度；“查看权限”是明确文字按钮，命中区至少 32px 高；
- 不使用 `opacity` 降低信息文字对比度。

系统角色示例：

```text
开发者  `developer`
查看用户分析
2 项权限                                      查看权限 ›
```

部门角色示例：

```text
研发部
研发部门基础访问权限
5 项权限                                      查看权限 ›
```

### 4.1 权限详情

不要继续在卡片下面原地展开。采用以下二选一，推荐 A：

**A. dialog 内右侧详情抽屉（推荐）**

- 点击“查看权限”后，从 dialog 右侧覆盖 320px 详情面板；
- 标题为角色业务名，下面显示角色描述；
- 权限按模块分组，中文说明在上、code 在下；
- 详情面板不改变角色卡片位置；
- Esc/关闭按钮只关闭详情，不关闭整个分配角色 dialog。

**B. Element Plus popover**

- 仅在实现成本需要严格收窄时使用；
- 宽 360px、最大高 420px、内部滚动；
- 必须处理 viewport 边缘定位和键盘焦点。

不要使用 tooltip 承载完整权限列表，也不要恢复原地展开。

## 5. 顶部摘要与搜索

### 用户上下文

标题只写“分配角色”，不要把长用户名全部塞进 dialog title。标题下单独显示：

```text
[顾] 顾世昌
     gsc
```

避免截图中的 `为「顾世昌 / 顾世昌」分配角色` 重复信息。显示逻辑：

- display_name 与 username 相同：只显示一次；
- 不同：主行 display_name，副行 username；
- display_name 为空：主行 username。

### 已选摘要

- 搜索框下方展示已选角色 chip，允许直接点击 × 取消；
- admin 永远不在摘要或候选中；
- 超过可用宽度时只显示前几个，末尾“另 N 个”，不要横向撑开 dialog；
- 顶部不再单独显示“已选 4 个”黑字，避免与 footer 重复。

### 搜索

- placeholder 简化为“搜索角色、说明或权限”；
- 搜索匹配角色名、业务显示名、描述、权限 code 和权限中文描述；
- 有搜索词时隐藏左侧分类导航的选中限制，右侧直接展示“搜索结果 N”；
- 无结果时展示搜索词和“清除搜索”按钮；
- 搜索不能导致已选角色丢失。

## 6. Footer 与变更语义

footer 左侧不再显示重复的“已选 4 个角色”，改成相对原始值的差异：

- 无变化：“尚未修改”；保存按钮 disabled；
- 有变化：“新增 2 个 · 移除 1 个”；
- 保存中禁止关闭和重复提交；
- 保存成功沿用现有接口行为，再关闭 dialog；
- 取消时若已修改，弹出“放弃角色修改？”确认；无修改直接关闭。

按钮：`取消` 为普通按钮，`保存角色` 为主按钮。不要用含糊的“确认”。

## 7. 颜色与细节

根据截图，本面板需要立即移除：

- 分组标题的 `border-bottom:2px solid #000`；
- 信息文字的 `color:#000 + opacity:*`；
- 纯文本三角符号 `▾/▸`；改用 Element Plus `ArrowDown/ArrowRight`；
- 选中行仅靠左侧 3px 色条的表达；
- 贴着 dialog 边缘的滚动区。

改用上一份审计建议的语义文字颜色：标题、正文、次级说明、禁用态各用不透明色值。主题主色只用于选中、焦点和主按钮。

建议不做：渐变、大面积投影、玻璃拟态、卡片浮动动画。这是权限工作台，目标是可信、清楚和高效。

## 8. 代码落点建议

当前 `page-users.vue` 已经同时承担用户表格、三个弹窗和大量角色展示逻辑。此次不要继续把 200 行模板/CSS 堆回页面。

建议拆出：

```text
src/components/admin/RoleAssignmentDialog.vue
src/components/admin/RoleSelectionCard.vue       # 可选；若内容很短也可留在 dialog
src/components/admin/RolePermissionDetail.vue
```

`page-users.vue` 只负责：

- 打开时传入 target user、allRoles、current role ids；
- 接收保存事件并调用现有增删角色接口，或由 dialog 接收明确的 submit callback；
- 保存成功刷新用户列表。

若不希望子组件直接调用 API，建议 dialog emit：

```js
emit('save', { userId, selectedRoleIds, addedRoleIds, removedRoleIds })
```

不要修改后端契约。

## 9. 必须覆盖的自动化测试

使用现有 Playwright API mock 和登录态注入：

1. 打开顾世昌的分配角色面板，display_name 与 username 相同时标题不重复；
2. 页面中不存在 admin 候选、admin checkbox、admin 已选 chip；
3. 初始 4 个角色均有明确 selected 卡片和顶部摘要；
4. 点击整张卡片能选中/取消，点击“查看权限”不会改变选择；
5. 权限详情打开后按模块显示中文说明和 code，关闭详情不关闭主 dialog；
6. 搜索角色名、中文描述、权限 code 都能命中；清除搜索恢复分类；
7. footer 正确计算新增/移除数量，无变化时保存 disabled；
8. 修改后点取消会确认，未修改时直接关闭；
9. 保存期间不可重复提交；保存请求仍只发送实际 diff；
10. 1920×1080、1366×768、1093×614、911×512、844×390 下：
    - dialog 不超出 viewport；
    - header/footer 始终可见；
    - 只有角色卡片区滚动；
    - 最后一张卡片可完整滚动到 footer 上方，不被遮挡；
    - 无页面级横向溢出；
11. 主题 A/B/C 下角色名、描述、权限数量、未选 checkbox 均清晰可读；
12. 键盘 Tab 可依次到达搜索、分类、角色卡、查看权限、取消、保存；Space 选择角色，Esc 分层关闭详情/主 dialog。

## 10. 人工截图验收

Claude 完成后不要只报 build/test 通过，至少附以下实际截图供对比：

- 1366×768：初始 4 个角色选中状态；
- 1366×768：权限详情面板打开；
- 1093×614：紧凑高度，滚动到最后一张卡片；
- 844×390：单列紧凑布局；
- 主题 A、B、C 各一张相同角色列表。

验收标准不是“所有字都能显示”，而是用户应在 5 秒内看清：正在给谁分配、现在有哪些角色、角色分别做什么、这次将新增或移除什么。
