## 🔴 P0 · 一个浮点编码让整份文件无法解析

`新.xlsx` 第 167 行的 `物料编码` 是 **`1399088.01`，被 Excel 存成 float**。
`_numeric_code_text` 对非整数浮点直接 `raise`：

```python
elif isinstance(value, float):
    if not value.is_integer():
        raise UploadValidationError(f'第 {cell.row} 行物料编码为非整数数值，请在 PDM 中设为文本')
```

于是**整份真实生产文件解析失败，一行都出不来**。

### 关键点：这一行本来就会被跳过

`1399088.01` 是含点的子件编码，文本化后含 `.`，命中既有的跳过规则：

```python
if '.' in code or code.startswith('14ST10'):
    continue
```

也就是说：**为了一行本来就不参与比对的数据，阻断了整个导入**。
代价与收益完全不成比例。

### 修法

非整数浮点**不要 raise**，转成文本后交给既有跳过规则处理：

- 用 `repr(value)` 得到最短往返表示（`1399088.01` → `'1399088.01'`，
  不要用 `str(int(value))` 或 `'%f'`，前者丢小数、后者补出 `1399088.010000`）；
- 转换后若含 `.`，既有规则自然跳过，无任何下游风险；
- 若确实担心精度（如 `1399088.010` 会丢尾随零），可以**告警/记日志**，
  但不应阻断整份文件。

保留 `raise` 的场合建议收窄为：`bool` 类型、或转换后为空字符串。

> 我在契约里写的是「建议对数字型单元格**明确报错或告警**」，措辞给了 raise 的空间，
> 这一条算我没写清楚。但实测结果说明必须选告警而非报错。

## 🟡 P1 · 产成品规格的版本位——我的契约写错了

### 现象

产成品两行的规格，PDM 分支与 ERP 分支结果不一致：

| 层次 | ERP 分支（解析后） | PDM 分支（当前） |
|---|---|---|
| 1 | `(V2.3)倾斜款手摇1.2米榉木木色_A02` | `(V2.3)倾斜款手摇1.2米榉木木色_A` |
| 2 | `(V2.3)手摇灰色_B02` | `(V2.3)手摇灰色_B` |

### 根因：责任在我的契约

我在契约 §4.4 里写「版本只取字母部分（`A02` → `A`，正则 `^([A-Za-z]+)`）」。
Codex **完全按契约实现了，实现本身没错**。

错在我的取证：我拿旧文件**原始「规格」单元格**（值是 `..._A`）做的基准，
**没注意到 ERP 分支会经过 `_complete_spec_version(spec, version)`**——
这个函数的存在意义正是把规格里只有字母的版本补全成完整版本：

```python
def _complete_spec_version(spec, version):
    """规格版本补全：若图号版本为 'D01'，而规格中含 '_D'（只有字母、缺数字），
    自动补全为 '_D01'。"""
```

所以**规范化后的产成品规格本来就该带完整版本**，`_A` 只是 ERP 原始单元格的写法。

### 为什么必须修

两个格式产出不一致会导致**假变更**：若变更前用 ERP 文件、变更后用 PDM 文件
（或反过来），同一个未变更的产成品会因为规格 `_A02` vs `_A` 被判定为"规格发生变更"。

### 修法

`_pdm_spec` 的产成品分支去掉字母截取，直接用完整版本：

```python
# 改为
return f'{prefix}{body}_{effective_version}'
# 而不是
match = re.match(r'^([A-Za-z]+)', effective_version)
suffix = match.group(1) if match else effective_version
```

**实测验证**：改后产成品两行与 ERP 结果**完全一致**，
`spec` 整体命中从 108/122 升到 **110/122**，
剩余 12 处**全部**是用户已澄清、明确表示不用管的版本分歧
（`14ST01010`/`14ST01030`/`14ST05038`/`14WD02068`）。
即**规格规则实际已 100% 正确**。

请同步更新对应测试的期望值（产成品规格断言应为 `_A02` 形态）。

## 需要用户注意的一点（非缺陷）

**当前的 `新.xlsx` 会被直接拒绝**，因为它仍有两列都叫「版本」。
这是**符合设计的正确行为**（P0 修好后依然如此）。

用户需要按之前说的，把第 19 列（`V2.3` 那列）**改名为「系列版本」**，
文件才能导入。产成品规格分支正是按「系列版本」这个列名取值的。

我验证时是复制一份、把第 19 列改名后再跑的。
