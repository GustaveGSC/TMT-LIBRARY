# ECR 变更申请单：能否改用新的 BOM 导出文件 · 数据分析

日期：2026-08-05
分析人：Claude
状态：**分析完成，有 3 项需用户决定，未动代码**

## 一、问题背景（用户原话）

> 研发工具里的「变更申请单填写」功能，当前导入的变更前和变更后文件有一个问题，
> 这个文件的来源比如变更后的内容里有一个全新的物料，那这内容就会全是空数据，
> 这样就会导致数据不准确。现在我用别的方法导出了一份可以用的文件，但是表头和内容不同。

根因清楚：旧文件是**从 ERP 导出**的，而全新物料还没进 ERP，所以那一行是空的。
新文件是**从 PDM / SolidWorks 导出**的，是设计源头，新物料必然存在。

## 二、两个文件的对照

样本：`旧.xlsx`（29 列，sheet `tmp2`）、`新.xlsx`（12 列，sheet `tmp`），
各 **174 个数据行**，`层次` 值**一一对应、零差异** —— 同一棵 BOM 树，只是来源不同。

| 旧（ERP，29 列） | 新（PDM，12 列） |
|---|---|
| 层次 / 快捷码 / 品号 / 品名 / 规格 / **图号** / 数量 / 单位 / **状态** / 备注 / 库存单位 / 品号描述 / 品号群组 / …（另有 16 列财务与工厂字段） | 层次 / 名称 / **物料编码** / **版本** / 数量 / 单位 / **适配产品** / **描述** / **表面处理** / **颜色** / 规格 / 品号群组 |

## 三、ECR 解析器实际需要什么

`backend/services/rd/change_documents.py::_parse_bom` 已经是**按表头名映射**（不是固定列号），
它需要 7 个字段，并且会**跳过**两类行：

```python
if '.' in code or code.startswith('14ST10'):
    continue
```

174 行里，解析器实际处理 **122 行**（跳掉 37 个含点的 PDM 子件 + 6 个 `14ST10` 标准件等）。

| 解析器需要 | 新文件是否有 | 结论 |
|---|---|---|
| `层次` | ✅ 直接有 | 完全一致 |
| `数量` | ✅ 直接有 | **174/174 完全一致** |
| `单位` | ✅ 直接有 | **174/174 完全一致** |
| `图号` | ❌ 无 | 可由 `物料编码 + '-' + 版本` 合成，**161/174 一致**（见 §4.1） |
| `品名` | ❌ 无 | **可由物料库按编码反查，命中率 100%**（见 §4.2） |
| `规格` | ⚠️ 有但含义不同 | 可由 4 字段合成，**131/174 精确**（见 §4.3） |
| `状态` | ❌ 无 | **无替代来源**，这是最大的功能性缺口（见 §5.1） |

## 四、已验证的三条规律

### 4.1 图号 = `物料编码` + `-` + `版本`

**161 / 174 一致。** 不一致的 13 行来自**仅 5 个编码**：

| 编码 | 行数 | 旧版本 | 新版本 | 分组 | 品名 |
|---|---|---|---|---|---|
| `14ST01010` | 6 | A01 | **B01** | 14ST | 原材料_标准件_螺钉_十字槽盘头尖尾自攻螺钉 |
| `14ST01030` | 2 | A01 | **B01** | 14ST | 原材料_标准件_螺钉_内六角平头倒边螺钉 |
| `14ST05038` | 3 | A01 | **B01** | 14ST | 原材料_标准件_家具五金_滑轨 |
| `14WD02068` | 1 | **B01** | A01 | 14WD | 原材料_木器_橡胶木_桌体左侧板 |
| `14WD02068.01` | 1 | **B01** | A01 | 14WD | （含点，解析器会跳过） |

⚠️ **方向是双向的**（11 行 A01→B01，2 行 B01→A01），所以**不是系统性偏移**，
而是 ERP 与 PDM 对这 5 个物料的版本记录**真实不一致**。见 §5.2。

另外：旧文件的 `品号` 与 `图号` 有 2 行不同（顶层产成品 `1201XGZM10-A` vs `1201XGZM10-A02`）。
解析器用的是 `图号`，而新文件合成结果与 `图号` 一致，**这两行没问题**。

### 4.2 品名 → 由物料库按编码反查（100% 可行）

新文件没有 `品名`，只有 `描述`（叶子名，如「活动桌面板」），
拼不出 ERP 的层级全名（如「原材料_木器_榉木_活动桌面板」）。

但**物料库刚好能补上这一块**：

- 新文件去重编码 **138** 个；
- 物料库（`import_product_raw`）查不到的 **43** 个，**全部是解析器本来就跳过的**
  （37 个含点 + 6 个 `14ST10`）；
- **解析器实际会处理的 95 个编码，物料库 100% 命中**；
- 按 `图号` 精确匹配时，122 行中 **120 行**能在物料库找到，品名可还原 **114/120**。

> 这是物料库模块带来的直接红利：如果没有 `import_product_raw`，这条路走不通。

**对于真正的新物料**（本需求的初衷），ERP 里按定义就没有品名，
所以只能退化为用 PDM 的 `描述` —— 这恰好也是唯一合理的来源。

### 4.3 规格 = `{适配产品}_{规格}_{表面处理}_{版本}`

四段用 `_` 连接（**不含颜色**）。空白归一化后 **131 / 174 精确一致**。

验证样例：

| 层次 | 旧规格 | 合成 |
|---|---|---|
| 1.1 | `XG23120J（倾斜）___A02` | 适配产品 + 空 + 空 + A02 ✅ |
| 1.1.1 | `XG23120J（倾斜）__W201（UV清漆）_A01` | 适配产品 + 空 + 表面处理 + A01 ✅ |
| 1.1.2 | `XG22120__M101（哑光白）_A01` | 同上 ✅ |

**43 处不一致全部是标准件**，原因单一：**旧文件第三槽有材质描述，新文件的「表面处理」列对标准件是空的**。

| 层次 | 旧规格 | 合成 | 差异 |
|---|---|---|---|
| 1.1.3 | `_M6×20_碳钢，镀镍_A01` | `_M6×20__A01` | 丢了「碳钢，镀镍」 |
| 1.1.6 | `_M6×12，耐落_碳钢，雾镍，8.8级_A01` | `_M6×12，耐落__A01` | 丢了材质与等级 |
| 1.1.15 | `_11.5×21.5×1.2_镀锌_A01` | `_11.5×21.5×1.2__A01` | 丢了「镀锌」 |

**注意：规格不能改从物料库反查。** 我试过了——BOM 里的规格是**上下文相关**的，
它的第一槽是「适配产品」，而物料主数据的 `spec` 那一槽是空的：

| 图号 | BOM 规格 | 物料库 spec |
|---|---|---|
| `14PL01159-A01` | `QM12120_（L=625mm）_C502（白） _A01` | `_（L=625mm）_C502（白） _A01` |
| `14ST09014-A01` | `TS15120H_内六角塑胶限位器_H6__A01` | `内六角塑胶限位器_H6__A01` |

所以规格必须按 §4.3 合成（新文件有「适配产品」，正好提供第一槽）。

## 五、需要用户决定的 3 件事

### 5.1 「状态」列缺失 —— 最关键

`validate_bom(path, role)` 现在靠状态列区分两个文件：

- `role='before'`：要求状态列**全部**为「已发布」
- `role='after'` ：要求状态列**不能全是**「已发布」

旧文件 174 行状态全是「已发布」。**新文件完全没有状态列**，
所以这套校验在新文件上无法成立，必须改。可选方向：

1. **取消这项校验**，改由用户在界面上明确指定哪个是变更前、哪个是变更后（最简单、最不容易误判）；
2. 用**版本号比较**代替：同一编码在两份文件里版本谁更高，谁就是变更后（但 §4.1 显示版本本身存在不一致，风险大）；
3. 从**物料库反查状态**（`import_product_raw.status`，重导后已有 265 条「失效」）——
   但那是物料主数据的启用状态，**不是 BOM 的发布状态**，语义不同，不建议。

我倾向 **方案 1**：文件来源已经变了，靠文件内容自证身份本来就脆弱，让用户显式选更可靠。
这需要改前端（`EcrForm.vue` 加变更前/后的明确选择）+ 后端校验。

### 5.2 5 个编码的版本不一致以哪边为准

`14ST01010` / `14ST01030` / `14ST05038`（ERP=A01，PDM=B01）
与 `14WD02068`（ERP=B01，PDM=A01）。

这不是格式问题，是**两个系统的版本记录真实不同步**。
改用新文件后这 5 个物料的图号会变，ECR 会把它们判定为"发生了变更"。
需要你确认：这 5 个到底是哪个版本，或者说以 PDM 为准是否可接受。

### 5.3 标准件的材质描述丢失是否可接受

改用新文件后，标准件规格会从 `_M6×20_碳钢，镀镍_A01` 变成 `_M6×20__A01`，
少了「碳钢，镀镍」「8.8级」这类材质与等级信息。涉及 43 行。
如果变更单必须带这些信息，需要在 PDM 导出里补「表面处理」列，或另找来源。

## 六、实施时必须注意的数据类型隐患

新文件的 `物料编码` 列**不全是文本**：**160 个 str + 13 个 int + 1 个 float**。

- `1301116` 被 openpyxl 读成 `int` → 必须 `str()`，否则字符串拼接会报错；
- 有 float 出现 → 若某个编码被 Excel 存成数字，可能出现 `1301116.0` 或科学计数；
- **前导零风险**：数字型单元格会丢掉前导零。本样本没有以 0 开头的编码，
  但旧文件里存在 `01.01.AD01002-21`、`03.ME.xxx` 这类以 0 开头的 ERP 编码，
  如果它们出现在 PDM 导出里就会被毁掉。**解析时必须按文本读取，
  或对数字型单元格明确报错，不要静默接受。**

## 七、结论

**新文件可用，规律是充分的**：数量/单位完全一致，图号可合成，品名可由物料库 100% 反查，
规格有明确的 4 段合成规则。核心障碍只有一个 —— **「状态」列没有替代来源**，
它决定了「变更前/变更后」的校验方式，必须先定 §5.1 的方案。

§5.2、§5.3 是数据质量问题，不阻塞实现，但会影响输出准确性，建议一并确认。

三项定了之后，改动落在 `_parse_bom`（支持两种表头格式）+ `validate_bom`（校验方式）
+ 物料库反查（品名），前端 `EcrForm.vue` 可能要加变更前/后的显式选择。
