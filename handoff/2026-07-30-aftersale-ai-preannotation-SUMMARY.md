## 一、这件事的来龙去脉

**最初目标**：用已人工处理的工单作参考，对 **2025 年 12 月**未处理工单做 AI 逐单预标注，
产出 Excel 供人工逐行审核。

**为什么改成回测**：第一次导数就发现原范围不成立——生产库**根本没有 `status='pending'`
的工单**（全库 2012 confirmed / 626 ignored / **0 pending**），2025-12 更是只有 8 单且全部
落在 `shipped_date=2025-12-31`（全库最早日期就是这天）。数据实际覆盖 2025-12-31 ~ 2026-06-30。

于是改为**回测式试点**：拿已人工处理的月份做持出集，剔除人工标签让 AI 盲标，
标完与人工结论逐条对比，量化准确率。这样能在真实积压到来前先验证方案。

## 四、沉淀下来的可复用组件

均在 `backend/scripts/aftersale/`，纯确定性代码、无外部依赖：

### 4.1 `model_matcher.py` — 型号匹配

复现人工的型号选择规则。**五个月系列层 91.8~94.3%**。

四条关键解读（都是实测确定的，按字面直接实现只有 36%）：

| 解读 | 影响 |
|---|---|
| 「销售时间在生命周期内」指**备注里的购买日期**，不是工单发货日期 | +10pp 以上；用发货日期比不过滤更差 |
| 「缺项取第一个」= 取**历史频次最高**的变体 | +16pp |
| **剔除外贸型号**，但保留 `both`（内外销共有确实参与售后，全历史 11 条） | +3pp |
| 外贸判定需 `market` **与**系列标识（FTP/含"外贸"）**双信号并用** | 单信号会漏（180 个外贸型号中 1 个 market 为空） |

其他细节：括号全半角混用（`蜻蜓 (V1.2）`）要兼容、录入简称（领航→领航员）要对齐、
销售名别名读产品标签「别名」分类（权威来源）、款/版归一、大小写不敏感、系列名取最长匹配。

### 4.2 `ignore_rule.py` — 忽略判定（机械部分）

只判两种**字面可判**的模式，不做语义推断：

- 含购买/已付/报价类词且**无故障描述** → 忽略
- 纯补寄/补发且**无故障描述** → 忽略
- 含补寄类词但**有**故障描述 → **不忽略**

实测精确率：2026-06 **96.3%** / 2026-05 88.0% / 2026-04 95.7%，召回约 42~46%。

**成败取决于故障词表完整度**：仅用常见词时"纯补寄"桶只有 53.8% 该忽略，
补上 `无法/不行/相差/旧的/暗/紧/涩/高低/不满意/要求换` 等后升到 77.8%。
词表见脚本内 `FAULT_RE`，经 2026-06 校准，勿随意删减。

召回低是设计使然——「表述含糊、找不到可推断问题」那类需语义判断，应交模型补充。

### 4.3 `material_hint.py` — 材质硬信号

从 `products` 的规范命名 `原材料_{材质大类}_{材质}_{部位}` 解析材质，
判实木/钣金（**备注文字判不出**："书架搁板掉漆"从字面看不出是木还是铁）。

| 材质大类 | → 一级分类 | 判别力 |
|---|---|---|
| 木器 | 实木问题 | 92.5%（强） |
| 金属件 | 钣金问题 | 66.7%（强） |
| 塑胶件 / 定制件 / 标准件 | 物料破损 / 主功能失效 / 次功能失效 | <60%，仅参考 |

四个月实测：覆盖 12.3~18.4%、命中准确率 77.2~86.5%。覆盖不高但覆盖到的部分明显更准。

## 五、业务规则库（来自用户 97 条 Excel 标注）

用户在 2026-03（42 条）和 2026-05（55 条）表里做的标注，是整个项目最有价值的输入。
完整规则见 `2026-07-30-claude-aftersale-rules-v3.md`（第二、三节）和 `-rules-v4.md`。

### 5.1 六类判定原则

1. **严重性优先**（一单多原因取更严重）：实木开裂>色差、破损>瑕疵、椅背/椅垫>椅轮、
   排插烧毁最高、开裂>少螺钉、靠背>直管
2. **部件归属**：旋转托盘→椅垫、电源线→电源；椅套独立于学习椅；不存在"升降托盘"
3. **部位决定分类**：实木件的瑕疵/色差/磕碰/开裂→实木问题；只有非实木件（灯罩/塑料件/
   桌垫/椅套）才归外观不良 ← **这条曾写错，导致实木问题召回从 83.6% 掉到 52.0%**
4. **「没提到就不能判」**：原因里的现象词（开裂/破损/异响/掉漆/不平）必须在备注有对应
   表述，否则退到该部位通用「失效」类。**但不要过度弃答**——能定部位不能定现象时给通用
   失效+中低置信，不要留空（三轮留空 20.7% 致总体准确率反降 10pp）
5. **功能问题 vs 破损/异响**：靠背松→椅背失效（非破损）、卡扣异常→失效（非异响）、
   无异响的椅轮问题→椅轮失效
6. **非产品问题**：客户自身原因→客户原因、发错物料→发错货、出现"重新发"→二次售后

### 5.2 词语 → 原因 确定映射

脏污→产品脏污、活动板翘/不平→桌面板不平、自动灭→学习灯不亮、磨损→实木磕碰划伤、
螺钉弯曲→螺钉破损、电流声→电流异响、电线问题→电线破损、鼓包/凹凸→实木瑕疵、
结疤→实木结疤、漆面不均→实木瑕疵、拉线坏→气弹簧拉线破损、安装造成→安装损坏、
电源滋滋响→电源异响、有气味→产品异味、卡簧→手摇把失效

### 5.3 收紧的判定

- **缺失类**：备注必须明确写"少/没有"某具体物料才判缺失；未提及**不得**判缺失
- 桌腿升降**指桌高升降**，只有倾斜才涉及气弹簧
- 「无法升降」是关键症状，优先于同时出现的生锈等

### 5.4 名称别名

- **销售名 ↔ 系统名**：权威来源是产品标签「别名」分类（category id=16，13 条，
  映射到具体系列编码，如 领航员Pro→LH21）
- **录入简称**（不在库里，代码维护）：领航→领航员（含 S/Z/A 变体）、
  学习工厂→学习工场、大白2代→大白二代、阳光款=阳光版

## 六、走过的弯路（避免重复）

| 弯路 | 教训 |
|---|---|
| 型号交给 LLM 逐单推理 | 二轮塌缩到 25 个唯一编码（系列 25.7%）。**确定性问题就该用确定性代码**，LLM 会被高频样本带偏 |
| 我写「瑕疵/色差/不平→外观不良」 | 过度泛化，实木问题召回 83.6%→52.0%。**要按部位区分，不能只看现象词** |
| 我写「只写寄什么物料就忽略」 | 方向反了——只含"补寄"无购买词的 88 单里 **83% 实际需处理**（"补寄X"隐含 X 缺失）。忽略精确率 100%→86.1% |
| 「没提到就不能判」执行过严 | 三轮留空 20.7%，已预测准确率略升但**总体降 10pp**。约束方向对，力度要控 |
| 只用 `market` 判外贸 | 有型号 market 为空但系列是 FTP，被漏掉。**双信号并用** |
| 我称"180 个外贸型号里 64 个无品牌后缀" | **错的**，是我正则的 bug（首字符须字母 + 3 字符下限，漏了 `2M2KIDS`/`PT`）。用户当时就质疑了 |
| 在调参月上报成绩 | 02 调规则、03 修 bug 后都不能再作评估月，否则是过拟合。**每轮必须换全新月份** |

## 七、未解决 / 待办

### 7.1 尚未解决的技术问题

1. **「其他」分类三轮 0~14% 召回**。已判定为兜底类、无稳定特征，建议接受人工兜底。
2. **错漏件召回 38~55%** 四轮都不高。
3. **钣金问题四轮波动大**（33.3→80.0→73.3→40.0）。五轮的材质硬信号就是针对它。
4. **多原因拆分四轮均未实现**（都是一单一条）。人工多原因单占比低（约 1~3%）。
5. **型号层上限约 73%**，且人工标注本身含噪声。四轮共 233 单「系列判对但型号不同」
   （25/76/66/66），已列入各轮 Excel 供抽查人工标注质量。

### 7.2 待用户处理

**原因词典三处调整（截至 2026-07-30 尚未落库，原因表最近变更 2026-07-07）**：

| 项 | 现状 | 用户意见 |
|---|---|---|
| 「安装痕迹」归在「外观不良」下 | 未改 | 不合理，应为「大白灯头磕碰划伤」，内部原因需重新划分 |
| 缺「学习灯控制失效」 | 不存在 | 自动变暗/变亮 需要这个原因 |
| 「升降托盘失效」 | 仍在 | 应为「旋转托盘破损」 |

**词典改完后需重新导出字典再跑下一轮**，否则相关单必然判不准。

### 7.3 用户的后续规划

用户已与售后人员沟通，**计划做一个记录模块**：让售后人员在模块里结构化记录数据再导出，
数据准确度会大幅提升。

按当前失败率排序，最值得结构化的四项：
1. **部位 + 材质**（选择而非文本）—— 今天靠 `products` 反推，覆盖率仅约 15%
2. **型号**（从候选选，而非写俗名）—— 今天要靠"俗名→系列→生命周期→历史频次"四层推断
3. **现象**（枚举）—— 今天要靠词表对齐"鼓包/凹凸/结疤/翘/不平"这些同义写法
4. **是否二次售后**（勾选）—— 今天靠"重新发"这类字眼猜

有了它，AI 的角色从"猜"变成"校验+补全"。但**本项目沉淀的规则依然有用**：
老数据回溯标注、录入人员漏填时的兜底都还要靠它们。
