# ECR 变更申请单：支持 PDM 导出的 BOM 文件格式，交接 Codex

日期：2026-08-05
状态：待实现
分析依据：`2026-08-05-ecr-bom-new-export-analysis.md`（含七轮验证过程，本文档是可执行契约）

## 一、背景与目标

**问题**：现有 ECR 导入的变更前/变更后 BOM 是**从 ERP 导出**的。
全新物料还没进 ERP，导出后整行为空，导致变更单数据不准确。

**方案**：改用**从 PDM / SolidWorks 导出**的 BOM 文件。PDM 是设计源头，新物料必然存在。

**范围**：**变更比对逻辑完全不变**（用户明确：「整体变更逻辑还是一样的，
只是导入的表格文件和之前不一样了，需要更新一下文件的处理方式」）。
本次只改**文件解析**这一层，`compare_bom` / `_next_version` / 输出模板都不动。

**必须保持向后兼容**：旧 ERP 格式的文件仍要能正常导入，不能只支持新格式。

## 二、两种格式的识别

| | 旧格式（ERP） | 新格式（PDM） |
|---|---|---|
| 特征列 | 有 `图号`、`品名` | 有 `物料编码`、`一级分类` |
| 列数 | 29 | 22（会变化，不要按列数判断） |

**按特征列判断**：表头含 `图号` → 旧格式；含 `物料编码` 且含 `一级分类` → 新格式；
两者都不满足 → 明确报错「无法识别的 BOM 文件格式」，不要静默按某种格式处理。

## 三、🔴 必须先处理：重复表头

新文件里**有两个列都叫「版本」**（第 8 列是物料版本 `A01`，第 19 列是系列版本 `V2.3`）。
用户已表示会把第 19 列改名为「系列版本」，但**代码不能依赖用户改对**。

现有 `_parse_bom` 的表头映射是：

```python
col_map[str(h).strip()] = c      # ← 同名列后覆盖前，静默无提示
```

后出现的列会**静默覆盖**先出现的。若直接喂当前这份文件，
它读到的是系列版本列（88 行为空），那 88 行因拼不出图号被**整行跳过且无任何错误**。

> 我自己的分析脚本就踩了这个坑，误报了一轮「导出丢了 88 行版本」。
> 这类缺陷不报错、只产出错数据，是最难发现的。

**要求**：
1. 建表头映射时**检测重复列名**；
2. 若重复的列名属于本格式的**必需字段**，直接 `raise UploadValidationError`，
   消息里带上重复的列名与它们的列号，例如
   「表头中「版本」出现了 2 次（第 8、19 列），请确认导出模板」；
3. 非必需字段重复时**取第一个**并可忽略，但不要静默取最后一个。

## 四、新格式字段映射（全部已在 174 行真实数据上验证）

解析器沿用现有的跳过规则不变：

```python
if '.' in code or code.startswith('14ST10'):
    continue
```

174 行中实际处理 **122 行**。以下命中率均以这 122 行为分母。

### 4.1 直接取列

| 目标字段 | 来源列 | 命中 |
|---|---|---|
| `level` | `层次` | 100% |
| `qty` | `数量` | 100% |
| `unit` | `单位` | 100% |
| `status` | `状态` | 100% |

### 4.2 图号 / 编码 / 版本

```
drawing = 物料编码 + '-' + 版本        # 「版本」取第一个同名列（物料版本，非系列版本）
code    = 物料编码
version = 版本
```

⚠️ **`物料编码` 必须按文本读取**。该列在样本中是 **160 str + 13 int + 1 float**
混合类型，`1301116` 会被 openpyxl 读成 `int`。

- 必须 `str()` 后再拼接；
- float 要防止出现 `1301116.0` 或科学计数；
- **前导零风险**：数字型单元格会丢前导零。样本里没有 0 开头的编码，
  但 ERP 侧存在 `01.01.AD01002-21`、`03.ME.xxx` 这类编码，
  一旦出现在 PDM 导出里就会被毁掉。建议对数字型单元格**明确报错或告警**，
  不要静默接受。

### 4.3 品名（100%，122/122）

```
name = '_'.join(非空的 [一级名, 二级名, 三级名, 描述])
```

其中「X 级名」= 该列值去掉 `代码_` 前缀后的部分：
`14_原材料` → `原材料`，`WD_木器` → `木器`，`04_榉木` → `榉木`。
三级为空时该段整体省略（**不要留空槽**）。

| 一级分类 | 二级分类 | 三级分类 | 描述 | → 品名 |
|---|---|---|---|---|
| `14_原材料` | `WD_木器` | `04_榉木` | 活动桌面板 | 原材料_木器_榉木_活动桌面板 |
| `13_半成品` | `01_桌面` | （空） | 桌面 | 半成品_桌面_桌面 |
| `12_产成品` | `01_桌类` | `XG_学习工场` | 桌面 | 产成品_桌类_学习工场_桌面 |

⚠️ **不要使用「四级分类」**。它只有 2 行有值（`ZM_桌面`、`ZT_桌腿`），
且其名称与 `描述` 重复，带上会得到 `产成品_桌类_学习工场_桌面_桌面`，
命中率从 100% 掉到 98.4%。

> 附带信息：`品号群组` = 一级代码 + 二级代码（`14`+`WD`=`14WD`），171/174 成立。
> **本次不需要用到**，记录备查。

### 4.4 规格（100%，两分支）

**分支判定**：`一级分类` 的名称部分是否为「产成品」。

**① 产成品分支**（本样本 2 行，均精确命中）：

```
spec = '(' + 系列版本 + ')' + 备注 + 类别 + 尺寸 + 材料 + 颜色 + '_' + 版本的字母部分
```

**各段之间无分隔符，直接拼接**；版本只取字母（`A02` → `A`，正则 `^([A-Za-z]+)`）。

| 组成 | 结果 |
|---|---|
| `(V2.3)` + `倾斜款` + `手摇` + `1.2米` + `榉木` + `木色` + `_A` | `(V2.3)倾斜款手摇1.2米榉木木色_A` |
| `(V2.3)` + 空 + `手摇` + 空 + 空 + `灰色` + `_B` | `(V2.3)手摇灰色_B` |

`系列版本` 即第二个「版本」列（用户将改名为「系列版本」，
**两种列名都要兼容**：优先找「系列版本」，找不到则取第二个「版本」列）。

**② 零部件分支**（120/122，差额均为已澄清的版本差异，非规格问题）：

```
spec = 适配产品 + '_' + 规格 + '_' + (表面处理 或 备注 或 颜色) + '_' + 版本
```

第三槽按 **表面处理 → 备注 → 颜色** 取**第一个非空值**。

⚠️ **不要把「材料」列加进第三槽**——实测会把命中率从 98.4% 降到 97.5%。

现有的 `_complete_spec_version(raw_spec, version)` 逻辑对新格式**不再需要**
（版本已直接拼在末尾），但**不要删除**，旧格式仍在用。

## 五、🔴 新物料的处理（用户给出的规则）

> 变更后的文件里，某一项版本是空的、状态是审核中，那这就是一个全新的物料，
> 变更后的版本为 **A01**。

即：**`版本` 为空 且 `状态` 处于审核中 → 全新物料，变更后版本记为 `A01`**。

对解析与推算的影响：

- 该行的 `version` 为空，`drawing` 无法按 §4.2 拼出 → **不能因此跳过该行**
  （现有逻辑 `if not level or not drawing: continue` 会把它丢掉，**必须改**）；
- 变更后图号 = `物料编码 + '-A01'`；
- `_derive_new_drawing` 目前对审核中行调 `_next_version(item['version'], ...)`，
  而 `_VERSION_RE` 匹配不了空字符串，会原样返回空 → **新物料要走单独分支直接给 `A01`**，
  不要进版本推算。

### ✅ 状态词表已由用户确认（2026-08-05）

> 「审核中」代表这个物料是一个新建的物料；
> 「通用变更审核中」和「非通用变更审核中」代表这个物料在变更前就已经存在，
> 只是版本的变动。

三个审核中状态**语义正交**，对应三种不同处理：

| 状态 | 含义 | 版本列 | 变更后版本 |
|---|---|---|---|
| `已发布` | 未变更 | 有值 | 保持原版本 |
| **`审核中`** | **新建物料**（变更前不存在） | **空** | **固定 `A01`** |
| `通用变更审核中` | 已存在，版本变动 | 有值 | 数字+1（`A01`→`A02`） |
| `非通用变更审核中` | 已存在，版本变动 | 有值 | 末位字母+1、数字重置（`A01`→`B01`） |

后两者是**现有已实现的行为，不要改动**。

### 需要新增的：`审核中` 分支

现有代码里 `审核中` 会**落到"非审核中"分支、返回原图号**，即被当作未变更处理 —— 这是缺口。
涉及三处，都要加对 `审核中` 的处理：

**① `_derive_new_drawing`（约 298 行）**

```python
if status not in ('通用变更审核中', '非通用变更审核中'):
    return item['drawing']          # ← 「审核中」落到这里，返回原图号（而它的图号是空的）
```

新建物料应返回 `f"{item['code']}-A01"`，**不要进 `_next_version`**
（`_VERSION_RE` 匹配不了空字符串，会原样返回空）。

**② `compare_bom` 的新增分支（约 455–463 行）**

```python
is_ecr_new    = a['status'] in ('通用变更审核中', '非通用变更审核中')
new_version   = _next_version(old_version, is_non_common) if is_ecr_new else old_version
new_drawing   = f"{a['code']}-{new_version}" if is_ecr_new else a['drawing']
```

`审核中` 目前 `is_ecr_new=False` → `new_version` 取空的 `old_version`、
`new_drawing` 取空的 `a['drawing']`，**产出一行空图号的新增记录**。
必须让 `审核中` 走：`new_version='A01'`、`new_drawing=f"{a['code']}-A01"`。

⚠️ `_update_spec_version(a['spec'], old_version, new_version)` 在 `old_version` 为空时
会拿空串去 replace，行为不可预期 —— 新建物料应**跳过这一步**，
它的规格里本来就没有旧版本可替换（规格末尾的版本槽由 §4.4 直接拼 `A01`）。

**③ 解析阶段不能丢行**

现有 `if not level or not drawing: continue` 会把新建物料整行丢掉
（它的 `版本` 为空 → 拼不出 `drawing`）。判定条件要改成：
`审核中` 且 `版本` 为空时，`drawing` 允许为空，用 `物料编码` 作为该行的标识参与比对。

**④ 建议：状态词表集中为常量并对未知值报错**

四个状态值目前散落在 5 处字符串字面量（138/175/300/302/373/383/459/460 行附近）。
建议提为模块级常量集合，并在解析时校验：**出现不在词表内的状态值就明确报错**，
不要静默当作「已发布」——否则 PDM 那边哪天改了措辞，会静默把变更行当成未变更。

## 六、`validate_bom` 不需要改

新文件有 `状态` 列，现有校验（before 全「已发布」/ after 不全是）继续成立。
只需确保它也能识别新格式的表头（它同样按列名取 `状态`）。

## 七、验收方式

1. 用**旧格式**文件跑一遍完整流程，结果与改动前**完全一致**（回归）；
2. 用**新格式**文件（`新.xlsx`，174 行）解析，逐字段核对：
   - 品名 122/122 与旧文件一致；
   - 规格 122/122 与旧文件一致（产成品 2 行走产成品分支）；
   - 图号除已澄清的 4 个物料外全部一致；
3. **重复表头**：构造一个含两列「版本」的文件，确认**明确报错**而非静默取最后一个；
4. **数字型编码**：构造一个编码为数字且含前导零的文件，确认报错或告警；
5. 格式识别：两种格式都能自动识别；构造一个都不匹配的文件，确认明确报错；
6. **新建物料**：构造一行「`状态=审核中` + `版本` 为空」，确认：
   - 解析阶段不被跳过；
   - 变更后图号为 `{物料编码}-A01`；
   - 规格末尾版本槽为 `A01`，且未被 `_update_spec_version` 破坏；
   - 在 `compare_bom` 中被判为「新增」。
7. **三种审核中状态互不干扰**：同一份 after 文件里同时包含
   `审核中` / `通用变更审核中` / `非通用变更审核中` 三种行，
   确认各自按上表推算（A01 / 数字+1 / 字母+1），互不影响。
8. **未知状态值**：构造一个状态为「草稿」之类的行，确认明确报错而非静默当作已发布。
