# 阶段2「数据丢失」结论更正：独立复核确认，非 bug

日期：2026-07-26

## 独立复核结果

用实际的 `product_finished_packaged` 组件关系表，对全部 13 个"疑似丢失"订单重新按公式验证：

```
原始组件数量 = Σ(非空 finished_code 的 quantity × 该成品关联组件数) + Σ(finished_code=NULL 的 quantity)
```

13/13 精确相等（容差 0.001）。同时直接查询确认 `2001JQ19-A` 关联组件为
`{2101JQZM12-A, 2101JQZT07-A}`、`2001JQ20-A` 为 `{2101JQZM13-A, 2101JQZT07-A}`，与 Codex 复核
报告描述完全一致。采纳 Codex 结论：**不是数据丢失 bug，是我最初的验收方法本身有问题。**

## 我的错误

直接比较 `SUM(原始 shipping_record.quantity)` 和 `SUM(shipping_order_finished.quantity)`，隐含
假设两者应该相等。但成品输出行记录的是"匹配到的成品套数"，一个成品若由 N 个组件构成，会从 N 个不同
原始组件码里各消耗一份，输出只记一次数量，不乘以 N。已记入 memory
（`feedback_multi_component_conservation_check.md`），以后任何涉及发货成品组合结果的核对都会先按
组件数加权，不再做未加权求和比较。
